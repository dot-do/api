# fn-customer-service — wave-zero substrate (GAP row, placeholder address)

The customer-service function's payable machine face, instantiated from
register row `fn-customer-service` per the property-template spec
(studio `docs/plans/2026-08-23-property-template-spec.md`).

**This is a GAP row.** No api-grammar name is held for the category
(api.support is grammar-implied, NOT held; gigs.support is a supply door,
not a candidate). Per spec §0 the full G3 substrate + anonymous sandbox are
built under a placeholder origin (`fn-customer-service.example.com.ai`) and
**no G4 brand config exists** until a name is acquired (#16). When it lands,
the origin string in `manifest.mjs` and the wrangler routes block are the
only lines that move.

## What serves

One substrate, two plies (same manifest rows, same envelopes, same rate rows):

- **Data face** — `GET /tickets` (the branching collection), `GET /tickets/{id}`,
  `GET /conversations`, `GET /deflections` (the deflection corpus, `generated`
  binding, CompanyType grain)
- **Headless helpdesk face** — `POST /tickets` (create, into the ephemeral
  anonymous sandbox workspace), `POST /tickets/{id}/resolve` (the seed tenant
  is read-only and answers BLOCKED)
- **The AXP quartet** — `/.well-known/agents.json`, `/openapi.json`,
  `/pricing`, `/llms.txt` — generated by the vendored `axp-faces` (0.3.0) at
  the ratified pin (`apis-ax-axp@2.6.0`, digest `a9a1197c…`) plus the ratified
  generator extension `axp-ext-rates-g2@0.2.0` (top-level `rates[]` in the
  Pricing Document, canonical camelCase `operationId` on every operation,
  `links.verify`, and the top-level `g2` card object — all native manifest
  inputs, never hand-rolled)
- **MCP door** — `POST /mcp` (JSON-RPC 2.0): `listTickets`, `getTicket`,
  `searchDeflections` — the same data functions the HTTP routes call
- **G2/G3 exposure** — `/icp.json` (the card's `links.icp`), `/substrate.json`
  (the `APIProduct` instance), `/verify` (claims as runnable probes, 3 faces)

All sandbox data is **labeled example data** — deterministic synthetic corpus
(`seed.mjs`): 952 demo prefixes, Example-surname people, example.com emails,
`example: true` on every record. The sandbox is the real product over
simulated data, never a faked demo.

Pricing is a **402-shaped stub, labeled as such** in the `/pricing` statement
(`binding: false`): the OFFER boundary is real and typed, rate rows price
from zero or carry free quotas, and nothing bills. Metering / money / receipt
**seams** are emitted as structured logs tagged
`{substrate, projection, motion, operation, shape, pattern}` plus identity
class and referral source (spec §7.4 — seams only, no billing logic).
